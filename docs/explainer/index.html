THE SERVICES / ONE FAKE TRANSFER

Follow one fake dollar.

Imagine moving one fake dollar from demo-a to demo-b. You click a button in the UI. It asks a caller process to act through that caller’s private Unix socket. The caller keeps its own credential.

At startup, the local SPIRE Agent measures each workload’s executable and deployment against registered selectors. The SPIRE Server signs short-lived certificates; the Agent delivers eligible identities through the Workload API and keeps them refreshed.

The trusted caller verifies Money’s SPIFFE ID, and Money verifies the caller’s certificate over mutual TLS. Money then checks the exact caller ID and payload before applying the transfer once per request ID. The unidentified caller fails TLS. The UI reads balances with its own read-only identity.

The browser operator is assumed, not authenticated. Anyone visiting the live demo can trigger these fake transfers.

RECEIVER / 01

Require and validate the client SVID

MTLSServerConfig requires a valid client certificate and verifies the SPIFFE credential. A missing or invalid certificate fails TLS before any HTTP handler runs.

func ServerTLS(svid x509svid.Source,
    bundle x509bundle.Source) *tls.Config {
    // SDK verification authenticates the SVID; exact route permission is applied
    // separately in the money handler. No application verification bypass.
    return hardened(tlsconfig.MTLSServerConfig(
        svid, bundle,
        tlsconfig.AuthorizeMemberOf(
            spiffeid.RequireTrustDomainFromString(
                "poc.internal"))))
}

RECEIVER / 02

Authorize the verified peer, method, and route

The ID comes from authenticated TLS state. Valid trust-domain membership is insufficient: only the exact trusted caller ID can transfer. credentialCurrent rejects expired credentials.

internal/money/server.go:18,42,55
func permitted(method, path, id string) bool {
    return method == "POST" && path == "/transfer" &&
        id == identity.Trusted.String() ||
        method == "GET" && path == "/balances" &&
        id == identity.Observer.String()
}

// Inside ServeHTTP, after TLS authentication:
    id := ""
    if r.TLS != nil && r.TLS.HandshakeComplete &&
        len(r.TLS.PeerCertificates) > 0 {
        if peer, err := x509svid.IDFromCert(
            r.TLS.PeerCertificates[0]); err == nil {
            id = peer.String()
        }
    }

    if !credentialCurrent(r) {
        write(403, map[string]string{"error": "credential_not_current"})
        return
    }
    if !permitted(r.Method, r.URL.Path, id) {
        write(403, map[string]string{"error": "forbidden"})
        return
    }

RECEIVER / 03

Validate the request before moving money

Money limits input size, rejects unknown fields and trailing JSON, and checks expiry again after reading. The ledger enforces the fixed transfer rules and identity-bound idempotency.

internal/money/server.go:67
    r.Body = http.MaxBytesReader(w, r.Body, 4096)
    decoder := json.NewDecoder(r.Body)
    decoder.DisallowUnknownFields()
    var request ledger.Request
    if err := decoder.Decode(&request); err != nil {
        write(400, map[string]string{"error": "invalid_bounded_json"})
        return
    }
    var extra any
    if err := decoder.Decode(&extra); err != io.EOF {
        write(400, map[string]string{"error": "invalid_bounded_json"})
        return
    }
    // Reading a bounded body can cross the peer credential expiry boundary.
    if !credentialCurrent(r) {
        write(403, map[string]string{"error": "credential_not_current"})
        return
    }
    result, status := h.ledger.Transfer(id, request)
    write(status, result)

03 / KEEP THE CLAIM PRECISE

Identity has a boundary.

01

A workload identity

PID identifies the requester during attestation. The issued SPIFFE ID names the approved workload. Several eligible processes can receive the same ID.

02

Measured at attestation

The executable hash and deployment are checked when attesting. This does not continuously measure process memory or protect an already compromised authorized process.

03

Separate from the human

SPIFFE authenticates the Go workload. The current learning demo explicitly assumes its human operator; anyone with browser access may trigger fake transfers.

TWO DIFFERENT REJECTIONS
No valid client certificateTLS fails before any Money HTTP response.
Valid credential, wrong permissionTLS succeeds; POST /transfer receives HTTP 403.
